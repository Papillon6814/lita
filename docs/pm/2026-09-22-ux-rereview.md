# 実装後の UX 再レビュー（2026-09-22、#38）

> 書く画面まで揃った状態で、2026-09-22 の UX 批評と同じ基準（Nielsen の 10 原則、UI 原則、WCAG 2.2）で全画面を見直した記録。対象のスクリーンショットは `npm run mock` の各シーン（下記）。

## 方法

Tauri なしで全画面を開けるよう、`src/platform/mock.ts`（ブラウザ用のモックホスト）を入れ、`VITE_LITA_MOCK=1` で切り替える。`npm run mock` → `http://localhost:1430/?scene=<名前>` を headless Chrome で撮った。シーン: signed-out / signing-in / codex-not-logged-in / codex-not-installed / intake / intake-loaded / building / voice / voice-open / write / write-generating / write-result / write-copied / write-over / write-error。GUI の自動操作（osascript）は他アプリに入力が飛ぶ事故があったので使わない。

## 指摘と対応

| # | 画面 | 指摘 | 原則 | 対応 |
| --- | --- | --- | --- | --- |
| 1 | 書く | 下書きがフォームの下に出るため、640px の窓では生成結果が見えない | 8 ミニマル・1 状態の可視性 | **下書きを最上部に置き、ブリーフは一行に畳む**（「ブリーフを直す」で開く） |
| 2 | 書く | コピー後も主ボタンが「コピーして採用」のまま。次に何をすればいいか弱い | 1 状態の可視性 | **主ボタンを「✓ コピーしました。投稿先に貼り付けてください。」に置き換え、「これは使わない」を隠す**。文章を直すと戻る |
| 3 | 書く | 「出す先」が選択肢 1 つのタブ。数字「280」がタブに載っている | 8 ミニマル・4 一貫性 | **出す先が 1 つのときは文字で「X（280 文字まで）」**。複数になったらタブに戻る（数字はタブに載せない） |
| 4 | 書く | 生成中に「← Voice」で戻ると Codex が走り続ける | 3 ユーザーの制御 | **戻るときに中止**する |
| 5 | 書く | 書くのにマウス必須 | 7 効率 | **⌘⏎ / Ctrl+⏎ で書く**。ボタン脇に小さく案内 |
| 6 | 書く | 下書きの到着が支援技術に伝わらない | WCAG 4.1.3 | **下書きの見出しにフォーカスを移し、`aria-live="polite"`** |
| 7 | 書く | 下書き枠の角丸が 16px でトークン違反（入れ物は 12px） | 4 一貫性 | **`--r-box`** に統一 |
| 8 | 書く | 「コピーする前に、文章を直せます。」の位置がボタンの下で読む順が逆 | 6 認識 | **下書き欄の直下**へ |

見直して問題なしと判断したもの: エラー文（平易な一文＋詳細）、生成中の説明（途中経過がない理由）、Voice 画面と取り込み画面（前回の批評から変えていない）、注意書き（#37 で修正済み）。

## 残したもの（バックログへ）

- **B-48 上限超えのときの「短く書き直す」** — 上限超えの警告は出るが、直す手段が手動編集か全文書き直ししかない。プロンプト側の対応が要る
- **B-49 ブリーフを戻っても保持** — 「← Voice」で戻ってまた開くとブリーフが消える。v0.1 では一枚しか画面がないので影響は小さい
