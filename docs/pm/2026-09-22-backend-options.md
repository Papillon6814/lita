# バックエンド基盤の選定（調査記録・要約）

> 正は Notion 子ページ「Lita — バックエンド基盤の選定（調査・候補比較）」です。ここは要約です。
> 調査日: 2026-09-22。各サービスの公式料金・ドキュメント・ステータスページを参照。

## 結論

**2026-09-22、Supabase（東京リージョン）に決定（D-40）。** 無料で始められ、Google ログインが組み込み、サーバコードをほぼ書かずに済み、素の Postgres なので逃げ道があり、Apache 2.0 でセルフホストもできる。この 5 点を同時に満たす候補は他になかった。弱点は 2026 年の障害の多さ。

次点は **Cloudflare Workers + D1**（月 $0〜5 固定、東京・大阪のエッジ。認証と API は自分で書く）。その次が **PocketBase を東京の VPS で自前運用**（月 $3〜6。個人メンテナーの pre-1.0）。

データは 1 ユーザーあたり数 KB のテキストだけなので、1,000 ユーザー規模でもどの候補も無料枠か最小構成に収まる。差は料金ではなく、安定性・リージョン・自分で書くコードの量・ロックイン。

## 前提

- Codex のログインはデータ引き継ぎに使えない。OpenAI 側に Lita が使えるストレージはない
- 生成は引き続き手元の Codex CLI で行う。サーバは保存と同期だけ
- 負荷の仮置き: 1,000 ユーザー × 1 日 20 操作 ≒ 月 60 万リクエスト、データ総量 100 MB 未満

## Google OAuth をデスクトップでどうやるか（共通）

- Google 公式は Desktop app クライアントで **ループバック `http://127.0.0.1:ランダムポート` ＋ PKCE を推奨・継続サポート**。ポート登録不要。OOB は 2023 年に廃止済み【確度：高】
- カスタム URI スキームは macOS の `tauri dev` で動かず Windows でも不安定という報告が複数。不要なら使わない【確度：中】
- 実装は `tauri-plugin-oauth` ＋ `openidconnect` / `oauth2` クレート
- 注意: 2025-06 以降クライアントシークレットは作成時のみ表示、**6 ヶ月未使用のクライアントは自動削除**。Desktop クライアントでシークレット省略時に `invalid_request` になる報告があり、**実機確認が要る**【確度：低】

## 外した候補と理由（要点）

- Firebase: セルフホスト不可、ロックイン最大
- Convex: 東京なし、ライセンスが FSL、デスクトップ認証は自前 JWT
- Appwrite: 東京なし、Tauri リリースビルドでの未解決 issue、2022 年以降資金調達なし
- InstantDB / Nhost: シード段階の小規模チーム、東京なし
- Vercel + Neon: Hobby は非商用限定、Neon は日本リージョンなし
- Turso: 東京はあるがロードマップが揺れている
- Deno Deploy: US/EU のみ、KV は永久ベータ
- AWS Cognito + DynamoDB: 最も成熟だが認証層が移せず、書くコードが最多
- Fly.io: Managed Postgres が $38 から。Railway: 東京なし、2026-05 に約 8 時間の全停止
- Hetzner / さくら / ConoHa: 運用が全部自分持ち。OSS のセルフホスト手順としては併記の価値あり
