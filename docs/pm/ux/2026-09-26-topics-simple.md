## 1．一言サマリー

**推奨は B（編集方針を一行にする）です。** 重さの正体は「毎回は変えない編集方針の 3 行が、毎回いちばん大きな面積を取っていること」と「『空でも出せます』を 3 回言っていること」です。B は機能を 1 つも消さずに、入れる場所を 5 → 2 に減らし、「題を出す」を約 190 px 上げます。代わりに、方針を直すときのクリックが 1 回増えます。いちばん削る C は入力欄 0 で最も軽く見えますが、「今回の方向」を捨て、方針が見えなくなるので D-61 の決め直しが要ります。

## 2．診断（いまの画面の何が重いか）

いまの画面（雲がある場合）で、題を出す前に目に入るもの:

| 種類 | 数 | 中身 |
| --- | --- | --- |
| 入れる場所 | **5** | 言葉（雲）、今回の方向、誰に向けて、持ち帰ってほしいこと、触れないこと |
| 説明の文 | **4** | 画面の説明、雲の使い方、雲の凡例、方針の「空でも出せます」 |
| 「空でも出せます」の繰り返し | **3** | 雲の「選ばなくても出せます」、方向の欄の中、編集方針の見出しの横 |
| 薄いリンク | 2 | 拾い直す、叩き台を作る |
| 主ボタン | 1 | 題を出す（y = 757 px） |

原則ごとの判定:

| 原則 | 判定 | 理由 |
| --- | --- | --- |
| 2 正常時は静か | △ | 説明の文が 4 つ。凡例は押す前から毎回出ている |
| 4 任意は任意に見せる | ✕ | 任意の入口が 5 つあり、それぞれが「空でも出せます」を言う。任意が多すぎて、**どれが本題かが 3 秒で分からない**。「空でも」を 3 回言うと、かえって「何か入れるべき画面」に見える |
| 5 その場で直す／畳まない | ◯ | 方針はその場で直せる。ただし「畳まない」の結果、**毎回は触らない方針の 3 行が、画面の 3 分の 1 を占める** |
| 6 空の状態は次の一手を 1 つ | ✕ | 本人の画面（`now-owner.png`）の「文章が増えると、よく書いている言葉がここに出てきます。」は、指す先に何も無く、次の一手も無い。約束だけの一文 |
| 10 手数で測る | △ | クリックは少ない（5 回）が、**飛ばす判断が 5 回**要る。題が出たあとは 10 題の下半分と「積む」が画の外（`now-topics-picked-tall.png`、「積む」は y ≈ 1100） |

頻度で見ると、この画面の中身は 3 種類が混ざっています。

| 頻度 | 中身 |
| --- | --- |
| 毎回 | 題を出す、題を選ぶ、積む |
| ときどき | 言葉を押す、今回の方向 |
| 最初に一度（まれに直す） | 編集方針の 3 行、文体と出す先 |

いまは「最初に一度」のものが「毎回」の行為より大きく、先に目に入ります。これが「複雑」の正体だと考えます。

## 3．どの案にも入れる手当て（共通）

1. **「空でも出せます」は主ボタンの隣で 1 回だけ**言う:「何も選ばず、空のままでも出せます。」。雲・方向の欄・方針の見出しからは消す。
2. **言葉が少ないときの一文を消す**。雲の箱ごと何も出さない（原則 6。次の一手が無い約束は出さない）。
3. **題が出たあとの「文体」「出す先」の 2 つの選択を 1 文に**:「自分の文章 の文体で note に書きます。変える」。「直近の記事と同じです。」は消す（1 文に言い換えたので不要）。「変える」を押すと、いまの 2 つの選択がその場に出る。
4. 雲の凡例（「よく書いている言葉ほど大きく…」）を常時は出さない。薄い言葉に指を載せたときに「もう書いた題材です」と出す（下の差し戻し 1）。

| | 中身 |
| --- | --- |
| 残す | 雲、今回の方向、編集方針の中身（一行で読める）、叩き台を作る（開いた中） |
| 消す | 共通の手当てのとおり |

## 6．推奨: B

1. **機能を 1 つも失わない。** 方向の欄も、方針も、叩き台も残ります。本人が以前に選んだもの（D-61 の B、D-66 の A）を壊しません。
2. **重さの原因だけを取る。** 重いのは「最初に一度」の方針が「毎回」の場所にいることでした。B は頻度どおりに大きさを付け直すだけです。
3. **「任意」が一目で分かる。** 入れる場所が 2 つになり、「空でも出せます」を主ボタンの隣で 1 回だけ言うので、「押せば進む」画面に見えます。本人のいまの状態（`b-5.png`）では、欄 1 つと一行と主ボタンだけです。
4. **C との差は「方向の欄」と「方針が見えるか」だけ。** B で使ってみて、方向の欄を誰も使わないと分かったら、そのとき C へ寄せられます（逆は戻しにくい）。

B の代償は原則 5「調整できるものは畳まない」に触れることです。一行に中身が読め、「直す」が常に見えているので、「調整できる」ことは伝わると考えます。採るなら原則 5 に「毎回は変えないものは、中身が読める一行にまとめてよい」を足します（下の論点 3）。

## 7．本人に決めてほしいこと

1. **編集方針は、この画面でどこまで見えていてほしいですか。** 3 行のまま（A）／中身だけ一行（B）／押すまで見えない（C）。
2. **「今回の方向」の自由記述は要りますか。** 言葉を押すだけで足りるなら C まで削れます。本人のように文章が少なく雲が出ない時期は、方向の欄が唯一の向け方です。
3. **原則 5 の書き足しを認めますか。**「毎回は変えないものは、中身が読める一行にまとめてよい（押せばその場で開く）」。B を採る場合に必要です。

## 8．要件へ差し戻したいこと（`lita-requirements` 宛て）

1. **雲の凡例を常時は出さない**（共通の手当て 4）。要件 `2026-09-24-topic-cloud.md` の受け入れ条件 6「書いた題材が薄く、意味が一文で分かり」に触れます。薄い言葉に指を載せたときの一文で足りるか、判断をお願いします。
2. **C を採る場合のみ**: D-61 の「一言の方向を添えられる」を外す、要件 `2026-09-23-article-queue.md` 必須 9（方針を書くと揃うことが 1 文で分かる）を緩める、の 2 点。

## 9．残る懸念

- 雲の使い方の一文（「押した言葉から題を出します」）を消すと、言葉が押せると気づくのが遅れるかもしれません。C はこれを画面の説明文に吸収しています。A・B で気になるなら、説明文を「言葉を押すと、その題材から題を出します。」に替える手があります（文は増えません）。
- B の一行は、方針が長いと末尾が切れます。3 項目を「／」でつなぐ形が読みにくければ、「誰に向けて」だけを出す形も試せます。
- 画はすべて静的な試作です。題を考えている間の一文、方針の叩き台を作っている間の一文は、いまと同じ場所に出す前提です。
