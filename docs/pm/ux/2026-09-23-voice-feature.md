## 追記: 根拠と確度の表示（2026-09-23）

厳密な読み取り（`docs/pm/requirements/2026-09-23-voice-quality.md` 必須 1〜3・13）で、項目ごとに材料からの引用と確度が付きました。本人の決定は「引用は見せる／話題の語は出さない／確度が低い項目に静かな印」です。D-58 の「8 項目を畳まずに静かに並べる」を壊さない形にしました。

### 決めたこと

| 論点 | 決めたこと | 理由 |
| --- | --- | --- |
| 引用の出し方 | 各行の「直す」の右に薄いリンク「根拠」。押すとその行の下に引用が最大 4 つ開く。もう一度押すと閉じる（ラベルは「閉じる」に変わる） | 常時出すと 1 行が 4 行になり、静かな一覧が読み物になる。畳むのは「調整できるもの」ではなく説明なので、原則 5 には触れない |
| 「根拠」の色 | ミントではなく薄墨（`.why`）。マウスを乗せるとミント | 主たる二次操作は「直す」。1 行にミントの下線が 2 本並ぶと、どちらを押す行なのか分からなくなる |
| 引用の見せ方 | 短い引用（左にミントの細い線）＋その下に出所の名前（例「note・kuno」）。出所は `voice_sources` の並び順から引く | 「どの文章から来たか」までが根拠。引用だけだと確かめようがない |
| 確度の印 | 確度が「低」の行にだけ、値の下へ薄い一文「材料が少なく、確かめきれていません。」。高・中には何も出さない | 数字は出さない（原則 2）。3 段のうち 2 段に何も出さないので、印が出た行だけが目に入る |
| 印の文言 | 「自信がありません」ではなく「確かめきれていません」 | 原因（材料の少なさ）と状態（未確認）を 1 文で言い、直してよいと分かる。感情の語を画面に置かない |
| 増えた項目 | 「組み立て」に 運び（`rhetoric`）・例と数字（`examples_and_numbers`）・かなで書く語（`kana_choices`）・しないこと（`never_does`）。**値があるときだけ**行が出る | 群を増やさず、既にある 3 群の最後に足す。空なら行ごと出ないので、古い文体は今日と同じ画に見える |
| 話題の語 | 出さない（データには持つ） | 本人の決定。生成に渡さない語を画面に置くと、直す対象だと誤解される |
| 計測値 | 出さない | 数字を出さない原則。文の長さも段落も画面には出さない |
| 絵文字の行 | 「根拠」を付けない | 脚注の 1 行で、リンクが 3 つ並ぶと脚注が主役になる |

```
あなたらしい言葉   エクイティ / ファイナンス / 構造   直す  根拠
                  ｜エクイティは返さなくていい金ではなく…
                    note・kuno
避けている言葉     絶対 / 最強   直す  根拠
                  材料が少なく、確かめきれていません。
```

## つなぐ中のローディング

要件: `docs/pm/requirements/2026-09-23-connect-loading.md`。実装は `src/components/SourceBox.tsx`（`RowState.working` に `done` / `total`）、`src/App.css`（`.src-working`）、`src/i18n/ja.ts` / `en.ts`（`import.listing` / `readingArticles` / `readingArticlesN` / `readingArchive` / `retry`）、`src/platform/mock.ts`（`import-progress` の配信と `intake-connecting` の自動開始）。

つなぐを押した行は、回るしるし（`.spinner`、13px）と一文だけを `.src-hint` の位置に出します。note は一覧を待つ間「記事の一覧を見ています」、本数が届いたら「記事を読んでいます（4／10 本）」に変わります。Medium は数字なしの一文、X は「アーカイブを読んでいます」。進捗バーも中止も足していません。行の高さは変わりません。

### 判定（撮影 1120×900、倍率 1、日本語）

| 受け入れ条件 | 判定 | 根拠 |
| --- | --- | --- |
| 1. 押した直後から終わるまで、しるしと一文が出る | ○ | `voice-feature/loading-intake-connecting.png`。`run()` が最初に `working` を立て、終わるまで戻さない |
| 2. 「（n／m 本）」の n が増えていく | ○ | 同 PNG が 4／10 の途中を捉えている。`onImportProgress` が `working` の行だけを書き換える |
| 3. 取り込み中も別の行を開いて貼れる。作業中の行は畳めない | ○ | 同 PNG で Medium・X・手作業が並んだまま。`close()` は `busy(service)` のとき何もしない（Escape も同じ道を通る） |
| 4. 失敗しても名前が残り、平易な一文が出る | ○ | `run()` の `catch` は入力を消さず `ErrorNote` を出し、ボタンは「もう一度つなぐ」に変わる |
| 5. X でちらつかない | ○ | `MIN_SPIN_MS = 600` を成功・失敗の両方で待ってから行を閉じる |
| 読み上げ・動きの配慮 | ○ | 一文に `role="status"` と `aria-live="polite"`、行に `aria-busy`。回転は `.spinner` の `prefers-reduced-motion` をそのまま使う |

手数は前後とも 3（行を開く・名前を入れる・つなぐ）で変わりません。
