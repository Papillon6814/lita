# 複数の発信プロフィール — UX 設計

## 受け入れ条件の判定

| 要件 | 判定 | UX 判断 |
|---|---|---|
| サイドバー最上部にラベル・選択名が常時見える | 満たす（設計） | ロゴ直下に「プロフィール / Profile」と選択名。Article/Editorを含む全画面で表示。 |
| プロフィールごとにデータが混ざらない | UX で判定不可 | UIの器は共通。データ分離は実装テスト事項。 |
| 選択状態が再起動後に復元される | UX で判定不可 | 切替直後に選択名を更新。永続化は実装検証事項。 |
| 既存データを初期プロフィールへ保持 | UX で判定不可 | 初期プロフィールは自動作成。本人が切替メニューから名前変更できる。移行保証は実装テスト事項。 |
| 新規プロフィール作成前に説明的な名前を必須入力 | 満たす（設計） | メニュー内のインライン入力。空白のみは作成不可。入力名を切替器に表示。 |
| 未保存Editor内容を保存してから切替 | 部分（設計） | 成功時だけ切替。失敗時は現在のEditor・選択・入力を維持し、既存の再試行を使う。 |
| キューは元プロフィールの記事へ結果保存 | UX で判定不可 | 切替後も既存状態表示。所有者固定・他プロフィール非変更は実装テスト事項。 |
| Googleログインは一つ | 満たす（設計） | 既存アカウントメニューを維持。別ログイン導線なし。 |

## 案・操作

サイドバーのロゴ直下にラベル付きプロフィール切替器を常時表示。開くとプロフィール一覧、現在選択中の印、区切り、「名前を変更…」「新しいプロフィール」のメニューを表示する。削除は対象外。記事・Editor・文体・題決めの3柱は増やさない。

**新規作成:** 「新しいプロフィール」を選ぶと、メニュー内が名前入力欄に置き換わり、自動フォーカスする。日本語の「発信先が分かる名前」／英語の “Name this publishing profile” を入力ラベルとし、Enterで作成、Escapeで中止。空白のみは作成できない。作成成功後に新プロフィールを選び、既存の空状態を表示する。作成操作中に現プロフィールの記事・Editor内容は変更しない。Editorから操作し未保存変更がある場合は、保存成功後にだけ切替。失敗時は作成/切替を完了せず、元のEditor・選択・入力を保ち、既存の再試行を利用する。

**初期プロフィール名変更:** 切替メニューの「名前を変更…」から、現在名を値とするインライン入力へ置き換え、自動フォーカスして文字列を選択。Enterで確定、Escapeで元の名前へ戻る。名前変更はデータや現在の画面・記事を変更せず、Editorの自動保存も不要。初期プロフィールは移行済み記事をそのまま持つ。

**キーボード:** 切替器でEnter/Spaceを押すとメニューを開き、フォーカスを選択中プロフィールへ移す。上下矢印で項目移動、Enterで選択。Escapeはメニューまたは編集中フォームを閉じ、切替器へフォーカスを戻す。プロフィールを選んだ後は切替器へフォーカスを戻す。入力欄内のEscapeは値を保存せず破棄してメニューへ戻る。

保存失敗時はプロフィールを切り替えず、同じEditorで入力を維持する。エラーは既存の自動保存失敗表示と再試行を使い、別の曖昧な通知を重ねない。キュー全体の停止条件が発生した場合は従来の表示に従う。

## 手数・既存画面への影響

通常切替は切替器→対象選択の2クリック。新規作成は切替器→新規→名前入力→作成（名前入力を必須とするのは誤った発信先選択を防ぐため）。改名は切替器→名前変更→確定。プロフィール変更は既存Article/Editorのデータ表示先のみを切替え、3柱や画面遷移の構造は変えない。未保存Editorの切替では保存完了を待つ。失敗時はEditorに留まる。

## 実装引継ぎ・検証

- `src/components/Sidebar.tsx`: ラベル付き切替器、一覧、menu rename/create状態、入力フォーカス・Escape操作。
- `src/components/Shell.tsx`: 切替前flush成功を待ち、失敗で現在プロフィール/route/入力を保持。切替中の連打を抑止。
- `src/components/Editor.tsx` / `src/hooks/useAutosave.ts`: 既存の保存失敗・再試行を維持。現在名は常設サイドバーに表示。
- `src/i18n/ja.ts` / `src/i18n/en.ts`: 上表の対訳を同じ意味で用意。
- `design/publishing-profiles.html`: 静的なメニュー・入力・失敗状態見本。

確認項目: 初期プロフィール改名で記事・版・Voice参照が変わらない。新規は説明的な名前が必須で、作成後は空状態。キーボードでメニューを開く・移動・作成/改名・Escape取消ができ、フォーカスが戻る。Editorで未保存変更中に切替要求し、保存成功なら切替・失敗なら同じEditorに入力を維持する。Aのキュー実行中にBへ切替後、Aの記事だけが更新されBは不変。

## 残る懸念

プロフィール名の重複可否・重複時の検証ルールは要件に明記されていないため、UXでは独自の制約を追加しない。説明的な名前を求める要件を満たす最小の入力だけに留める。移行・データ分離・再起動復元・キュー所有者固定はUXだけで検証できず、実装テストが必要。HTMLモックはCDNに依存せず、ローカルフォント名の後にシステムフォールバック、色は既存トークンのみを使う。
