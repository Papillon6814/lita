## 4．直してほしいこと（lita-dev へ）

### 4-1．切替が成功したら、フォーカスを左下のボタンに戻す（要修正）

- 今: `Sidebar.tsx` の `chooseProfile` は成功時に `profileButtonRef.current?.focus()` を呼ぶが、この時点でボタンは `profileBusy`（`disabled`）のままなので効かず、フォーカスが `<body>` に落ちる
- 期待: 切替が成功してメニューが閉じたら、`profileBusy` が外れた直後にフォーカスが左下のボタンに乗る。Tab・Enter で続けてメニューを開き直せる。作成（`submitProfile` の create）でも同じく、成功後に戻る先（今はメニューの選択中の行）にフォーカスが乗っていることを確かめる
- 失敗したとき（保存失敗・切替失敗）はメニューを開いたままにし、フォーカスは押した行に残す（今と同じ）
- 確かめ方: `?scene=profiles-menu` で「個人発信」を押したあと `document.activeElement` が `.sidebar .acct` であること。文言・見た目の変更は無し

## 5．残る懸念（マージを止めない）

| 懸念 | 内容 | 扱い |
|---|---|---|
| 保存失敗で切り替わらないとき、メニューの側では何も変わらない | 失敗の表示は本文の右上、押した場所は左下で、画面の対角にある。前の最上部の切替器より遠くなった。押しても何も起きないように見え、もう一度押す人がいる（押しても再試行になるだけで害は無い） | UX 設計の「別の通知を重ねない」を今は保つ。実機で本人が戸惑ったら、メニュー内の一文（例:「記事を保存できないため、切り替えていません。」）を lita-ux が設計して別に出す |
| 切替・作成・改名そのものの失敗（`profileError`）の画が無い | mock に失敗させる道が無い。置き場所（一覧の直後、フォームの中）は妥当 | mock に失敗のシーンを足せるときに撮る |
| 長い名前の全文がどこにも見えない | ボタンでは全角 8 字ほど、メニューでは 11 字ほどで切れる。頭が同じ長い名前が 2 つあると区別しにくい | 想定は数件で短い名前（原則 6）。困ったら `title` で全文を出す案を検討 |
| 作成フォームの主ボタンが名詞（「新しいプロフィール」） | 原則 9「動詞で終える」から外れる。D-78 の設計から引き継いだ文言で、この PR の変更ではない | 次に文言を触るときに「作成する／Create」へ。今回は直さない |
| 改名のヒントの ja/en の差 | ja「Escapeで元に戻す」、en "Escape to cancel"。D-78 から引き継ぎ | 同上 |
