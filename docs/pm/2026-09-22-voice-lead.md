# Voice の一文の精度（2026-09-22、#39 / B-45）

> Voice 画面の先頭の一文が、長文や英語の Voice で不自然にならないかを確かめ、直した記録。

## 分かったこと

- 抽出プロンプトは「値はサンプルと同じ言語で書く」と指示している。だから **UI が日本語で英語の Voice** を読むと、旧テンプレートは「あなたの文章は、常体でanalytical and skeptical」と言語が混ざった
- 旧テンプレートの敬体判定は「formal」を含むかで見ていたため、英語の **"informal" を敬体と誤判定**していた
- tone に句が入ると（「分析的で、読者に問いを投げかけながら進める」）一文が崩れる
- 一文を Codex に書かせると、同じ 1 回の抽出で「あなたの文章は、硬めの常体で冷静かつ懐疑的に、「先に」「何を」で判断軸を問い、断定や反問で閉じる。」が返った（61 秒、追加コストなし。`cargo run -p lita-codex --example one_line`）【確度：高、実機 1 回】

## 実装

1. **`VoiceProfile.one_line`** を追加（`#[serde(default)]`、表示専用で `generation_view()` には出さない。テストで確認）。抽出スキーマの description で「サンプルの言語で、『あなたの文章は、』相当で始め、丁寧さ・トーン・特徴語・締め方を具体的に、日本語 70 字以内」と指示
2. Voice 画面は `one_line` があればそれを出し、無い（2026-09-22 より前の）Voice は **テンプレート**で組む。一文は詳細の先頭行「一文」から直せる
3. テンプレート（`src/summary.ts`）は **UI の言語ではなく Voice の言語**で組む。informal / casual / 常体 / だ・である を先に常体と判定。長すぎる tone・語・文末は使わない。何も無ければ「まだ十分に読み取れていません」

テンプレートの出力例（9 ケースを `tsx` で確認）:

| 入力 | 出力 |
| --- | --- |
| ja 常体、分析的・懐疑的、のだろうか。 | あなたの文章は、常体で分析的で懐疑的。エクイティやファイナンスといった言葉を使い、「のだろうか」で締める。 |
| ja 語彙なし | あなたの文章は、敬体で率直で前向き。「ました」で締める。 |
| ja 文末なし | あなたの文章は、常体で淡々。なるほどやつまりといった言葉を使う。 |
| ja 空 | あなたの文章の特徴は、まだ十分に読み取れていません。 |
| en informal | Your writing is plain, analytical and skeptical. It leans on words like equity and runway, and closes on “I think”. |
| en 長い句のみ | Your writing is plain. |

## 残り

- `preferred_words` に「先に」「何を」のような汎用語が混ざる（抽出側の既知の弱点、`2026-09-22-voice-schema.md`）。一文にもそれが出る。抽出プロンプトの語彙指示を強めるのは別件
- 一文の言語が Voice の言語になるので、日本語 UI で英語 Voice のときは一文だけ英語になる。これは意図どおり（値が英語なので混ぜるより読める）
