# よく書いている言葉の雲から、書く題を出す

- 出所: 本人の言葉「記事案をだしていくとき、ワードクラウドっぽい UI を試してみたい。どう実現していくのがいいか」（2026-09-24）。聞き取りで「雲に並べるのは題材の語（元にした文章・過去記事・編集方針から拾ったテーマ語。よく書くほど大きい）」「語は Codex に拾わせる」「選んだ語を種にして題を出す」「まず静的な試作を 2〜3 案見てから Rust を配線する」
- 関係する決定: D-44、D-51、D-53、D-57、D-59（**整理が要る。改訂ではない**）、D-61、D-63
- Issue: #108

> **D-59 との関係（衝突ではありません）。** D-59 で決めた `VoiceProfile.topic_words`（話題の語）は、**文体の理解の副産物**です。「渡すと無関係な記事に前の話題が混ざる」ため、本文の生成には渡さず、画面にも出していません。今回の言葉の雲は**題材を選ぶための別の器**で、保存場所も渡し先も別です（雲は `user_settings` に持ち、題を出すプロンプトにだけ入る）。**`VoiceProfile.topic_words` は今回も触らず、本文の生成の契約（D-28 / D-29 / D-59）も変えません。** 雲を `topic_words` から作ることもしません（文体の材料と題材の材料は範囲が違う。必須 2）。

## 目的

書く題を決めるとき、本人は白紙の「今回の方向」を前にして、自分が何について書いてきた人なのかを毎回思い出しています。自分の言葉を目に見える形で並べ、そこから 1〜3 個つまむだけで、その題材の題が 10 出るようにします。

## 利用者の状況

本人（唯一の利用者、D-51）が記事一覧から「題を出す」を押し、「書く題を決める」（`TopicPicker.tsx`、D-61）に来ます。いまの画面は、編集方針 4 行と、空の「今回の方向」1 行と、主ボタン「題を出す」です。

「今回の方向」は空でも押せますが、空のまま押すと題が広く散ります。かといって何を書けばいいかは、その場では出てきません。本人は自分の過去の文章を頭の中で思い出して一言に縮める作業を、題を出すたびにやり直しています。

本人が持っている材料（元にした文章・過去の記事・編集方針）には、その人が繰り返し戻ってくる言葉が既に入っています。それを見える形にして押せるようにすれば、「思い出して書く」が「見て選ぶ」に変わります。

## 必須

1. 「書く題を決める」の画面に、**本人がよく書いている言葉を大きさの違う語として並べた場所**がある。大きさは「よく書いている度合い」を表し、**数字・順位・件数は一切出さない**（原則 2）。
2. 言葉は **Codex に拾わせる**。材料は **元にした文章（`voice_sources` のピース）・過去の記事（題と本文の頭）・編集方針**の 3 つ。文体プロファイル（`VoiceProfile`）からは作らない。
3. 一度に拾う言葉は **20〜40 個**（狙いは 30）。1 語は日本語で 2〜10 字の名詞句、英語で 1〜3 語。言語は文体の言語に従う（`topics::Lang::of`）。一般語（「こと」「仕事」「今日」）、人名・社名、固有の数値は入れない。
4. 各語は **「よく書いている度合い」の重み**を持つ。重みは**出現回数ではなく、その人が繰り返し戻ってくる度合いとして Codex に 1〜5 の 5 段階で付けさせる**。段階の値は画面に出さず、**語の大きさ 3 段階**（弱 1〜2 / 中 3 / 強 4〜5）に畳んで見せる。
5. 各語は **「もう書いた題材かどうか」の印**を持つ。拾うときに過去の記事の題と突き合わせて Codex に真偽で返させる（材料には既に渡している）。**書いた語は薄く**見せ、**それでも押せる**。~~凡例は一文だけ（例「薄い言葉は、もう書いた題材です」）。~~ →凡例は常時は出さず、薄い言葉に指を載せたとき・キーボードで移ったときに一文で出す（2026-09-26 改訂、D-71）。
6. 雲は **`user_settings` に 1 枚だけ持つ**（`topic_cloud jsonb`）。中身は 語・重み・書いたかの印・拾った時刻・拾ったときの材料の数。**文体ごとには持たない**（編集方針と同じ粒度、D-61）。新しいテーブルは作らない。
7. 雲を拾うのは次の 2 つのときだけ。**(a) 雲がまだ無く、材料があるとき、画面を開いた時に 1 回だけ自動で**。**(b) 本人が「拾い直す」を押したとき**。材料が増えても勝手には拾い直さない。
8. 前に拾ったときより**材料が増えているときだけ**、雲のそばに薄い一文で拾い直せることを伝える（例「新しい文章が増えています。拾い直す」）。増えた本数は出さない。
9. 拾うのは **10〜20 秒**かかる。**段階表示はしない**（D-23、Codex は一括で返す）。**中止できる**。
   - 自動（7a）のときは雲の場所に一文だけ出し、**主ボタン「題を出す」は押せるまま**にする（雲が無くても題は出せる）。
   - 「拾い直す」のときは**前の雲をそのまま残した上で静かに差し替える**（原則 2）。まっさらにしない。
10. 言葉は**押して選べる**。選べるのは **1〜3 個**。3 個選んだら、それ以上は押せなくなり、選べる数を一文で伝える（`topics.limit` と同じ扱い）。**もう一度押せば外れる**。**0 個でも「題を出す」は押せる**（原則 4）。
11. **主ボタンは「題を出す」1 つのまま**（原則 3）。言葉を押しただけでは題は出ない。「拾い直す」は薄いリンクか「…」に置く。
12. ~~選んだ言葉と「今回の方向」は**併用する**。「今回の方向」の欄は消さない。選んだ言葉は**題材**、方向は**今回の角度**として、**題のプロンプトでもブリーフでも別々の行として渡る**（「題材: A、B、C」と「今回の方向: …」が混ざらない）。~~ →**「今回の方向」の欄は消す。選んだ言葉は雲の中で色が変わるだけで、題のプロンプトとブリーフに「題材」の行として渡る**（2026-09-26 改訂、D-71）。
13. 積んだ記事のブリーフ（`brief_for`）にも、選んだ言葉が**題材の行として 1 行**入る。長さの行と「調べない」の行は今までどおり残る。
14. **題を出し直しても選んだ言葉は残る**。**拾い直すと選択は消える**（語そのものが入れ替わるため）。
15. 材料が無いとき（元にした文章も記事も無い）は**雲の場所ごと出さない**。いまの画面（編集方針＋今回の方向＋題を出す）のままにする。文体が無いときは既存の案内（`topics.needVoice`）が先。
16. ~~拾えた言葉が **5 個に満たないときも雲を出さない**（まばらな雲は雲に見えない）。代わりに一文で、文章が増えると言葉が出てくることを伝える。~~ →下限は **3 語**。下限に満たないときは約束だけの一文を出さず、文章を足す次の一手を 1 つ出す（2026-09-26 改訂、D-71・D-72。`2026-09-26-topics-press-only.md` 必須 11、`2026-09-26-gather-writing.md` 必須 1・8）。
17. 拾えなかったとき（Codex の失敗）は、**雲の場所に平易な一文と次の行動**を出し、**画面の残りはそのまま使える**（原則 7）。前の雲があるならそれを残す。
18. 画面の語は **「言葉」**（見出しは「よく書いている言葉」相当）。「ワードクラウド」「タグ」「キーワード」「トピック」「重み」は画面に出さない（原則 1）。編集方針の「よく書く題材」とは別物だと、見出しと置き場所で分かる。

## 任意

- 選んだ言葉を「今回の方向」の欄の近くに、選んだ順で薄く再掲して、何が効いているかが一目で分かるようにする。
- 言葉の上にカーソルを置いたとき、その語を含む元の文章の一節を 1 つだけ薄く見せる（根拠。D-59 と同じ考え方）。
- 書いた語を隠す切り替え（「まだ書いていない言葉だけ」）。
- 雲を編集方針の「よく書く題材」へ流し込む導線。

## やらないこと

- **本文の生成の契約を変えること。** 言葉は題のプロンプトとブリーフにだけ入る。`generation_view()` には一切入らない（D-28 / D-59）。
- **`VoiceProfile.topic_words` を画面に出すこと、雲の材料にすること、統合すること。** 触らない。
- 言葉を本人が手で足す・消す・言い換える編集機能。拾い直すだけにする。
- 言葉ごとの件数・割合・推移・期間での絞り込み。数字は出さない（原則 2）。
- 文体ごとの雲、記事ごとの雲。アプリに 1 枚だけ。
- 雲から直接記事を書き始めること（押したら本文まで行く）。題を選ぶ工程（D-61）を飛ばさない。
- 雲をエディタや記事一覧など「書く題を決める」以外の画面に置くこと。
- 語の共起・関連線・クラスタの可視化。
- 形態素解析ライブラリの導入。数えるのは Codex の仕事にする。

## 受け入れ条件

1. 材料がある状態で「書く題を決める」を開くと、大きさの違う言葉が並び、数字も順位も出ていない。
2. 言葉を 3 個まで押して選べ、4 個目は押せず、その理由が一文で分かる。もう一度押せば外れる。
3. 言葉を 1 つも選ばなくても「題を出す」が押せる。主ボタンは画面に 1 つだけ。
4. 言葉を選んで「題を出す」を押すと、その題材に沿った題が 10 出る。~~「今回の方向」に一言を足しても、題材と方向の両方が効いている。~~（2026-09-26 改訂、D-71: 方向の欄は廃止）
5. 「拾い直す」を押している間、前の言葉がそのまま見えていて、中止でき、中止すると前の言葉のままになる。
6. もう書いた題材の言葉が薄く見え、その意味が~~一文で分かる~~ →指を載せたとき・キーボードで移ったときに一文で分かる（2026-09-26 改訂、D-71）。薄い言葉も押せる。
7. 材料が無い状態で開くと、雲の場所ごと無く、いままでどおり題が出せる。

## 本人に聞かずに決めた既定値

| 項目 | 決めた値 | 理由 |
| --- | --- | --- |
| 画面の語 | 「言葉」（見出し「よく書いている言葉」） | 編集方針の「よく書く題材」と、D-59 の「話題の語」と、画面上で衝突しない。原則 1 |
| 拾う語の数 | 20〜40（狙い 30） | 20 未満だと雲に見えず、40 を超えると大きさの差が読めない。1 画面に収まる上限 |
| 重みの意味 | 頻度ではなく「繰り返し戻ってくる度合い」を Codex が 1〜5 で付ける | 素の出現回数は一般語が上位に来る。形態素解析は入れない（やらないこと） |
| 大きさの段階 | 3 段階（1〜2 / 3 / 4〜5） | 5 段階の差は 30 語の中では読めない。3 段階なら大小が 1 秒で分かる |
| 保存先 | `user_settings.topic_cloud jsonb`（新しい列 1 つ） | アプリに 1 枚。行が 1 つしか無いものに新しいテーブルは要らない。`policy` と同じ置き方（D-61） |
| 拾い直しの契機 | 初回の自動 1 回と、本人が押したときだけ | 材料が増えるたびに 10〜20 秒を勝手に使わない。増えたことは一文で伝えるに留める（必須 8） |
| 選べる語の数 | 1〜3（0 でも進める） | 4 つ以上を種にすると題が散り、雲を使う意味が消える。5 本まで積める（D-61）と桁を揃えた |
| 語と「今回の方向」 | ~~併用。語は題材、方向は角度~~ →方向の欄は廃止、語だけ（2026-09-26 改訂、D-71） | 直交する。置き換えると「採用寄りで」のような角度の指定ができなくなる |
| 語が無いとき | 雲ごと出さない（必須 15・16） | 空の雲は「壊れている」に見える。原則 6（空の状態は次の一手を 1 つだけ） |
| 書いた題材の印 | 出す。薄く、押せる | 本人の関心は「まだ書いていないこと」。拾うときに一緒に返せるので計算は増えない |
| 拾う時間の見せ方 | 自動は静かに一文、押したときは前の雲の上で差し替え、どちらも中止可 | 原則 2。D-23（段階表示はしない） |
| 語の言語 | 文体の言語に従う（`Lang::of`） | 題・方針・ブリーフと揃える |
| 拾ったあとの選択 | 出し直しでは残る、拾い直しでは消える | 語そのものが入れ替わるので、消さないと押していない語が選ばれたままになる |

## 残る質問

1. **雲の言葉から編集方針の「よく書く題材」を埋めたいですか。** いまは別物として並べます（任意に置きました）。同じものに見えるなら、編集方針側の行を雲に置き換える案もあります。
2. **もう書いた題材を薄くするだけで足りますか。** 隠す切り替えまで要るなら任意から必須へ上げます。
3. なし（3 つ目は既定値で進められます）。

## lita-ux への引き継ぎ

**やること**: 静的 HTML で **2〜3 案**を作り、本人に見せて 1 つ選んでもらってください。Rust の配線はそのあとです（本人の指定）。既存のモックの scene 名は `topics` / `topics-picked` なので、試作は同じ画面の差し替えとして見えるようにしてください。

**本人に判断してもらう軸**（これが案の違いになるところ）:

1. **雲の形。** 自由配置の本物のワードクラウドか、大きさの違う札を行で流すか、中心に大きい語を置く同心円か。読みやすさと「雲らしさ」は逆を向きます。
2. **語を押した後の流れ。** 選んでから主ボタンを押す（必須 11 の既定）か、押した語が「今回の方向」の欄へ流れ込んで見えるか。**押した瞬間に題が出る案は作らないでください**（主ボタンが 2 つになります）。
3. **雲の置き場所。** 編集方針より前か後か。編集方針は「いつも同じこと」、雲は「今回の材料」です。

**守る制約**:

- 主ボタンは「題を出す」**1 つだけ**（原則 3）。「拾い直す」は薄いリンクか「…」。
- **数字・順位・件数を出さない**（原則 2、必須 1）。大きさだけで伝える。
- **動きは控えめに。** 並び替えのアニメーション、ホバーでの拡大、浮遊は入れない。選択は色の変化だけ。
- **色はトークンから**（原則 8）。選択はミント `#1d7f70`、重みはインク `#2b2a27` の濃淡と字の大きさ、「書いた」は薄さ。新しい色を足さない。
- 語は最大 40 個、日本語 2〜10 字。**いちばん長い語といちばん多い数で崩れないこと**を試作で確かめてください。
- 選択の上限に達したときの見せ方（押せない語がどう見えるか）を案に含めてください。
- 拾っている間（10〜20 秒）と、拾えなかったときの画も 1 枚ずつ撮ってください。
