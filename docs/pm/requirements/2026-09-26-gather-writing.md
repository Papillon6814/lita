- 出所: 本人の言葉「言葉の雲を出すのがすごく大事だからこの方法を考えよう。こここそそのユーザーの言葉をたくさん収集できる仕組みについて真剣に考えないといけないかもしれないね」（2026-09-26。案 C の弱点「文章が少なく雲が出ない人は、題を向ける手段が無い」への返事）
- 関係する決定: **D-72（新）**、D-71（新）、D-43、D-57、D-59、D-60、D-65、D-66、D-70、D-42（Slack 凍結）、D-44、D-51
- 改訂する既存の要件: `2026-09-24-topic-cloud.md` の必須 16（雲を出す下限）
- 前提にした現物: `crates/lita-codex/src/topics.rs`（`cloud_prompt`・`samples_block`・`SAMPLE_HEAD_CHARS = 400`・`MAX_SAMPLES = 24`）、`src-tauri/src/lib.rs`（`topic_material`・`material_count`・`gather_topic_cloud`）、`src/components/TopicPicker.tsx`（`MIN_WORDS = 5`・`showCloud`・`fewWords`）、`src/components/SourceBox.tsx`・`PasteBox.tsx`、`crates/lita-sources`（note・Medium・X）、`docs/pm/handoff.md`（本番の文体の材料）
- Issue: #129

## 目的

案 C（D-71）で、言葉の雲は題を向ける**唯一の手段**になりました。雲が出ない人は、押すものが 1 つも無い画面に立たされます。**その人の文章そのものを集めて、最初の起動から雲が出るまでの距離を縮めます。** 入力欄で埋め合わせることはしません（D-72）。

## 必須

### 1. その場で文章を足す

1. **雲が出ないとき**（材料が無い、言葉が下限に満たない）、「書く題を決める」の雲の場所に**次の一手が 1 つだけ**出ます。薄いリンクまたは一文＋リンクで、主ボタンは「題を出す」のままです（原則 3・6）。約束だけの一文は出しません。
2. 押すと、**画面を離れずに**既存の取り込み部品（自分の文章を貼る欄・.txt/.md を落とす場所・note／Medium／X をつなぐ行、D-60・D-65）がその場に開きます。モーダルにしません。閉じれば元に戻ります。
3. 足した文章は、**直近の記事の文体**（D-55 と同じ選び方。文体が 1 つならそれ）の「元にした文章」に入ります。文体ページの「元にした文章」に、1 本 1 行で同じものが並びます。
4. 文章を足しても**文体は学び直しません**。学び直すかは今までどおり文体ページで本人が選びます（D-57）。
5. 足し終えたら、**画面を離れずに自動で言葉を拾い**、雲が出ます。拾っている間の見せ方と中止は、今の「拾う」と同じです（D-66 必須 9）。
6. 文章 0 本の文体（おすすめの文体、D-70）でも同じ次の一手が出ます。文体が 1 つも無いときは、今までどおり「まず文体を作りましょう」が先です。

### 2. 取りこぼさない

7. **言葉が下限に満たない雲が保存されていても**、そのあと本人の文章が増えていれば、画面を開いたときに**自動で 1 回拾い直します**。言葉が十分な雲は、今までどおり自動では拾い直しません（D-66 必須 7 を維持）。
8. **雲を出す下限を 5 語から 3 語に下げます**（雲の要件の必須 16 を改訂）。Codex への指示は「材料が支える数だけ。最大 40（狙い 30）」に変え、材料が少ないときに一般語で水増しさせません。
9. **雲を拾うときに読む量を広げます。** 24 本・各 400 字の上限を雲では外し、**全部の文章を、全体 40,000 字の中で読みます。** 1 本あたりは全体を本数で割った長さ（最大 2,000 字。頭と末尾から取る）で、本数が多いほど 1 本は短くなりますが、落とす本はありません。題を出すとき（`topics_prompt`）の読み方は変えません。
10. **材料の数（「新しい文章が増えています」の判定）は、本人の文章だけで数えます**: 元にした文章の本数＋本人が直した記事の本数（必須 11 の定義）。Lita が積んで書いただけの記事では増えません。

### 3. 使うほど育つ

11. **本人が直した記事の本文を材料に入れます。** 「直した」とは、Lita が最後に書いた版（`generated`・`shortened`）から本文が変わっている記事、または Lita が一度も書いていない記事です。Lita が書いたままの記事の本文は入れません。題と 1 行目は今までどおり「もう書いた題材」の判定に使います。
12. 本人が直した記事を材料に入れても、**生成の契約（D-28・D-29・D-59）と文体は変えません**。雲のプロンプトにだけ入ります。

### 共通

13. **数字を出しません**（本数・字数・語数・「あと n 本」）。取り込み部品が既に出している表示（「n 本として読みます」など）はそのままです（原則 2）。
14. 取り込みや拾うのに失敗したときは、既存の平易な一文を出し、**画面の残りと「題を出す」は使えるまま**です（原則 7）。前の雲があれば残します。
15. 画面の語は「文章」「元にした文章」「言葉」。「学習」「ソース」「材料」「データ」は出しません（原則 1）。

## 任意

- 任意の URL から 1 本ずつ取り込む（洗い出しの 4）。
- つないだ note・Medium の新しい記事を、この画面を開いたときに静かに取り込む（5）。
- .docx・.pdf の取り込み（6）。
- おすすめの文体を選んだ直後に、文章を足すと題の言葉も出ることを一文で伝える（7）。
- 雲の言葉に指を載せたとき、その言葉が出てくる本人の文章の一節を 1 つ見せる（雲の要件の任意と同じ）。

## やらないこと

- **話題・題材を書かせる欄**、雲に言葉を手で足す機能、オンボーディングの質問（D-72）。
- Slack・Google ドライブ・メールなど新しい連携先（D-42、審査と権限の壁）。
- Lita が書いたままの本文、Lita が出した題、積んだだけの記事を材料にすること。
- 題材のための別の置き場所（新しいテーブル・新しい名前）。足した文章は「元にした文章」に入る（残る質問 1 で変わりうる）。
- 文体の自動の学び直し（D-57）。
- 題を出すとき（`topics_prompt`）の材料の読み方を変えること（待ち時間に効くため）。
- 案 C の画面の組み立て（`2026-09-26-topics-press-only.md`）を変えること。

## 受け入れ条件

1. おすすめの文体だけ（文章 0 本・記事 0 本）で「書く題を決める」を開くと、雲の場所に次の一手が 1 つだけあり、約束だけの一文は無い。
2. その一手を押すと画面を離れずに貼る欄とつなぐ行が開き、1,500 字ほどの自分の文章を 1 本貼って足すと、画面を離れずに言葉が拾われて雲が出る。
3. 足した文章が文体ページの「元にした文章」に 1 本 1 行で並び、文体の 8 項目は変わっていない。
4. 言葉が下限に満たない雲が保存された状態で文章を足し、この画面を開き直すと、「拾い直す」を探さなくても自動で拾い直して雲が出る。
5. 文章を 30 本つないだ状態で拾い直すと、25 本目以降の文章にしか出てこない題材も雲に入る。
6. 記事を 3 本積んで書き上がっただけでは「新しい文章が増えています」は出ず、そのうち 1 本の本文を本人が直してから開くと出る。
7. 取り込みに失敗しても平易な一文が出て、「題を出す」は押せる。

## 本人に聞かずに決めた既定値

| 項目 | 決めた値 | 理由 |
| --- | --- | --- |
| 足した文章の置き場所 | 直近の記事の文体の「元にした文章」 | 新しい名前と置き場所を作らずに済む（原則 1）。文体は自動で学び直さないので、足しただけでは文体は変わらない。**本人の答えで変わる**（残る質問 1） |
| 次の一手の数 | 1 つ（貼る・落とす・つなぐは開いた先に並ぶ） | 原則 6。入口を 3 つ並べると、どれを選ぶかの判断が要る |
| 足したあとの拾い方 | 自動で 1 回 | 足した目的が雲なので、もう一押しさせない。D-66 の「勝手に拾わない」は、本人が足した直後には当たらない |
| 雲を出す下限 | 3 語 | 案 C では雲が唯一の向け方。まばらでも 3 語あれば向けられる。1〜2 語は選ぶ余地が無い |
| Codex に求める語の数 | 材料が支える数だけ、最大 40 | 少ない材料で 20 語を求めると一般語で水増しされる |
| 雲が読む量 | 全部の文章を全体 40,000 字の中で。1 本は全体÷本数（最大 2,000 字、頭 3：末尾 1） | 本数で切ると後ろの文章の題材が丸ごと落ちる。題材は文章の頭と締めに出やすい。文体の予算（80,000 字）の半分にして、拾う時間を今の 10〜20 秒から大きく延ばさない。**実装時に本物の材料で時間を測り、60 秒を超えるなら全体を下げる**（仮置き） |
| 「直した記事」の判定 | Lita が最後に書いた版から本文が変わった記事、または Lita が書いていない記事 | 版（D-45・D-46）で判定でき、新しい列が要らない |
| 材料の数の数え方 | 元にした文章＋直した記事 | 「増えています」は本人の言葉が増えたときだけ点くべき |
| 分け方 | 3 つの束（取りこぼさない → その場で足す → 使うほど育つ）を 1 つの Issue、PR は束ごと | 束 2 は小さく、詰まりの不具合を含むので先に出す |

## 残る質問

1. **この画面で足した文章は、文体の「元にした文章」に入ってよいですか。** 既定は「入る」です（次に学び直すと文体にも効く）。題材を集めるためだけに、文体に効かない別の置き場所がほしいなら、新しい保存先と名前を作ります。作るものが変わるので聞きます。
2. **本人の文章は、note・Medium・X のほかにどこにありますか**（会社のブログ、プレスリリース、自分のサイトなど）。多いなら、URL から取り込む（任意の 1 つ目）を必須に上げます。

## 案 C（`2026-09-26-topics-press-only.md`）と Issue・PR を分けるか

**分けます。** 理由は 4 つです。

1. **中身の種類が違う。** 案 C は画面と文言だけで、Rust と DB に触りません。こちらは Rust（雲の材料の読み方・数え方・直した記事の判定）と、新しい画面の設計（その場で足す）が要ります。
2. **確かめ方が違う。** 案 C はモックの画で判定できます。こちらは本物の材料で Codex を回し、拾う時間と語の質を測る必要があります（必須 9 の仮置き）。
3. **決まっている度合いが違う。** 案 C は形まで決まっています（`simple-c.html`）。こちらは残る質問 1 の答えと、lita-ux の設計がこれからです。
4. **待たせる理由が無い。** 案 C を先に出しても、雲が出ない人の画面はいまと同じく何も押せない状態で、悪くはなりません（いまの「文章が増えると…」は次の一手の無い約束なので、消えても失うものは無い）。

**順番**: 案 C（#128）を先に出す → この要件の束 2（取りこぼさない。詰まりの不具合を含む）→ 束 1（その場で足す）→ 束 3（使うほど育つ）。束 2 は残る質問の答えを待たずに始められます。

## lita-ux への引き継ぎ

### 頼むこと

必須 1〜6 の「その場で文章を足す」を、案 C の画面（`c-4.png` の空いた場所）に入れる設計をしてください。静的 HTML で 1〜2 案、撮る場面は 4 つ: ①文章 0 本で開いた ②次の一手を押して取り込み部品が開いた ③貼って足した直後に言葉を拾っている ④雲が出た。

### 守る制約

- **主ボタンは「題を出す」のまま**（原則 3）。次の一手は薄いリンクか一文＋リンク。取り込み部品の中の「足す」ボタンが主ボタンと並んで見えないようにする。
- **次の一手は 1 つ**（原則 6）。「貼る」「つなぐ」を並べるのは開いた先で。
- **約束だけの一文を出さない。** 一文を置くなら、同じ行に押せる次の一手がある形に（例「自分の文章を足すと、よく書いている言葉がここに出ます。 文章を足す」は可。数字は入れない）。
- 取り込み部品は**既存のものをそのまま使う**（`SourceBox.tsx`・`PasteBox.tsx`、D-60・D-65）。この画面のために別の貼る欄を作らない。
- 語は「文章」「元にした文章」「言葉」。「学習」「材料」「ソース」を出さない（原則 1）。足した文章が文体の「元にした文章」に入ることは、言うなら開いた部品の中で一文だけ。
- 案 C の画面の組み立て（入力欄 0・主ボタン 1・編集方針はリンク）を崩さない。
- 色・角丸・書体はトークンから（原則 8）。
