## 目的

案 C（D-71）で、言葉の雲は題を向ける**唯一の手段**になりました。雲が出ない人は、押すものが 1 つも無い画面に立たされます。**その人の文章そのものを集めて、最初の起動から雲が出るまでの距離を縮めます。** 入力欄で埋め合わせることはしません（D-72）。

### 日常の文章の集め先（2026-09-26 追記）

本人の回答で、公開記事の外にまとまった文章は少なく、**日々書いている量はチャットやメールのほうが多い**ことが分かりました。雲にとって大事なのは「何について書いているか」なので、口語のチャットでも題材の語はよく出ます。一方で、チャットには**他人の発言**と**社内の話**が混ざります。経路はこの 2 点で選びます。

#### 守る条件（AGENTS.md・既存の決定から）

| 条件 | 中身 |
| --- | --- |
| Lita の運用サーバを持たない・テレメトリなし | 取り込みは手元で読んで、本人の文章だけを既存の保存先（`voice_sources`、Supabase、D-36・D-40）に入れる。書き出しファイルそのものはどこにも置かない |
| 審査や権限の壁を越えない | Slack の API は凍結（D-42）。Gmail の読み取りは制限付きスコープで審査が要る。API を使わない経路にする |
| 他人の発言を混ぜない | 保存するのも Codex に送るのも本人の発言だけ。他人の発言は読んだその場で捨てる。本人の発言の中の他人のメンションも消す |
| 本人が選ぶ | 何を入れたかが「元にした文章」で見え、1 行で外せる（D-57）。入れる前に、入れたくない会話を外せる |

##### Codex に他人の発言を渡すか

**渡しません。** 理由は 4 つです。

1. **他人が選んでいない。** 同僚の発言は、その人が Lita にも OpenAI にも渡すと決めていません。本人の文章を本人が選んで渡すのとは違います（D-74 の「他人の発言は保存も Codex への送信もしない」をそのまま守る）。
2. **会社のデータである。** 職場のチャットの中身は会社のもの（Slack の User Terms の Customer Data など）で、本人が自分の発言だけを使うより、他人の発言ごと外に出すほうが重い。
3. **抜くのに言葉の理解が要らない。** 「誰が書いたか」は見出しの形で分かり、意味を読む必要がありません。手元の見分けで足り、待ち時間も 0 です。
4. **言い換えが起きない。** 雲と文体の材料は本人の原文そのものが要ります。Codex に抜かせると、言い換えや他人の文の混入を検べる手立てが要ります。

Codex に渡るのは、今までどおり「元にした文章」に入った本人の発言の本文だけです（雲を拾うとき・文体を学び直すとき）。

##### 推奨（P）の根拠

1. **本人の手間が最も少ない。** 初回に名前を 1 つ押すだけで、2 回目からは貼って「足す」だけです。アプリの追加・設定・検索の記法は要りません（本人の「使いにくくならないか」）。
2. **道具を問わない。** 見るのは「名前＋時刻の見出し → 本文」の骨組みだけで、道具の名前を当てません。Slack の画面が変わっても、骨組みが残る限り動きます。
3. **他人の発言が手元から出ない。** 読んだその場で捨てます。保存するのは本人の発言の本文と、この端末に覚えた本人の名前だけです。
4. **誤りから抜けられる。** 見分けを誤っても、名前の一覧に「全部が自分の文章」があり、今の貼り付けと同じに戻せます。見分けられなければ最初から今の貼り付けです。

弱点は、**自分の発言に名前が付かない道具**（Teams の一部など）と、**続けて書いた 2 つ目以降に名前が省かれる形**です。後者は「名前の無い本文は、直前の見出しの人のもの」とします。前者は、名前の無い本文のかたまりが候補に「名前の無い発言」として出るので、本人がそれを選べば足ります（必須 19）。

### 4. 日常の文章から集める（2026-09-26 追記、同日 2 回改訂。段 4、D-77）

書き直す前の必須 16〜25 のうち、最初の版（Slack の書き出し ZIP を落とす行）は本人が書き出しを取れないため**取り下げ**て任意（段 5）に、2 番目の版（Slack の検索結果の貼り付け、D-76）は本人の「slack に拘泥しない方法がいい」で**道具を問わない形に置き換え**ました。

16. **入口は既存の「自分の文章を貼る」欄（`PasteBox`）だけです。** 段 2 で「書く題を決める」から開く欄、文体の入口、文体ページの「元にした文章」のどこでも同じ動きです。「書いた場所からつなぐ」の器に行は足しません。**道具の名前（Slack・Teams・LINE など）で分かれる画面・ボタン・タブ・案内は作りません。**
17. 欄の中に、**チャットやメールの会話を貼っても自分の発言だけが残ることを 1 文だけ**置きます（趣旨「チャットやメールの会話をそのまま貼っても、自分の発言だけが残ります。」）。道具の名前、検索の記法、手順、数字は出しません。
18. 貼られたものに**「名前（と時刻）の見出し → 本文」の骨組みが繰り返し見つかったら**、会話として扱います。見分けの手がかりは道具の名前ではなく形です: 時刻・日付の語（`10:23`、`午前 10:23`、`10:23 AM`、`昨日`、`今日`、`2026/09/26` など）を含む短い行、同じ短い名前が行頭に 2 回以上現れる形（`名前:`、`名前 タブ 本文`、`[時刻] 名前:`）、メールの「〜 wrote:」「〜 のメッセージ:」の行。名前の無い本文は直前の見出しの人のもの、時刻だけの行は直前の人の続き、とします。日本語と英語の画面の両方で見分けます。
19. 会話として扱ったら、**貼った中の話者の名前を候補として並べ、本人を 1 回選びます**（名前だけ。数字・発言の数は出さない）。一覧の最後に **「全部が自分の文章」** を置き、選べば今までの貼り付けと同じに戻ります。自分の発言に名前が付かない形（名前の無い本文のかたまり）は「名前の無い発言」として候補に出ます。**選んだ名前はこの端末に覚え**（複数の名前を覚えてよい。道具ごとに表示名が違うため）、次から候補に覚えた名前があれば聞かずにその人の発言として扱い、**欄の中の 1 文に、誰の発言として足すかを名前で出します**（「変える」で選び直せる）。覚えた名前が候補に無ければ、名前が 1 人でも聞きます（同僚 1 人の長い発言を本人の文章として入れないため）。
20. 選んだ直後、足す前に、**何が残るかが欄の中で見えます**（本人の発言の本文だけが並んだ姿。会話のときは「n 本として読みます」「1 本にまとめる」の代わりに、「自分の発言だけを残します」の趣旨の一文）。1 件ずつ外す一覧は作りません。外したいものは貼る前に選び直せば足ります。
21. 残すのは本人の発言の**本文だけ**です。見出し（名前・時刻・日付）、画面の文字（「スレッドに返信」「編集済み」「n 件の返信」「メッセージを表示」など、日本語と英語）、リアクション、リンクのプレビュー、ファイルの名前、メールの「〜 wrote:」以下と `>` で始まる引用、本文の中のメンション（`@名前`）、URL（表示の文字だけ残す）、絵文字の記法（`:smile:`）、コードの塊を捨てます。
22. **1 回の貼り付けは 1 本の文章**として「元にした文章」に入ります（`kind` は `paste` のまま、`origin` で会話から残したと分かる印。**DB の migration は要らない**。道具の名前は記録しない）。行の名前は「自分の発言」と貼った日で、1 行目の本文ではありません。**前に会話から入れた発言と同じ発言は二度入れません**（本文が同じ発言を除く）。すべて重なっていたら何も足さず、平易な一文で伝えます。
23. **保存するのも Codex に渡すのも本人の発言の本文だけ**です。他人の発言・他人の名前・クリップボードの元の中身は、手元で読んだその場で捨て、アプリのデータにもサーバにも Codex への指示にも残しません。貼る欄の下書きにも残しません。この端末に覚えるのは**本人が選んだ自分の名前だけ**で、サーバには送りません。**話者を見分けるのに Codex は使いません。**
24. **会話の骨組みが見つからないときは、今までの貼り付けと同じに扱います**（空行で分ける、エラーにしない。確認も挟まない）。ただし**時刻らしい行が繰り返しあるのに話者を分けられないとき**だけ、欄の中に平易な一文（趣旨「誰の発言か見分けられませんでした。このまま足すと、全部が自分の文章として入ります。」）を出します。「足す」は押せるままです（止めない）。選んだ人の発言が 1 つも残らないときは、平易な一文で伝えて何も足しません（原則 7）。
25. 見分けと切り出しは、**画面が変わっても直しやすい形**にします（手がかりを 1 か所にまとめ、テストに見本を持つ）。見本は少なくとも Slack（日本語・英語）・Teams・LINE の .txt・Discord・メールの返信・`名前: 本文` のログ・**会話でないふつうの文章**（「」の会話文を含むエッセイ、`Q:` `A:` のインタビュー）の 8 種類。見本は架空の名前と文で作り、本人の本物のコピーは commit しません。ふつうの文章の見本では会話として扱われないこと（インタビューは扱われても「全部が自分の文章」で戻せること）を確かめます。

足した直後の動き（画面を離れずに自動で言葉を拾う、文体は学び直さない、学び直せば文体にも効く）は必須 5・4 と同じです（**文体に効いてよいことは本人の回答で確定、2026-09-26**）。

`site/privacy.html` は変えません。入るのは今までどおり「本人が貼った文章」で、扱うデータの種類は変わらないためです（任意で「会話を貼ったときは本人の発言だけを残す」の一文を足してよい）。

## 受け入れ条件

1. おすすめの文体だけ（文章 0 本・記事 0 本）で「書く題を決める」を開くと、雲の場所に次の一手が 1 つだけあり、約束だけの一文は無い。

3. 言葉が下限に満たない雲が保存された状態で文章を足し、この画面を開き直すと、「拾い直す」を探さなくても自動で拾い直して雲が出る。
4. 文章を 30 本つないだ状態で拾い直すと、25 本目以降の文章にしか出てこない題材も雲に入る。
5. 記事を 3 本積んで書き上がっただけでは「新しい文章が増えています」は出ず、そのうち 1 本の本文を本人が直してから開くと出る。
6. 他人の発言が混ざった会話を、Slack（日本語の画面）・LINE の .txt の中身・メールの返信の 3 つからそれぞれコピーして貼ると、初回だけ名前の一覧が出て本人を選べ（2 回目の貼り付けからは聞かれず、欄の 1 文に本人の名前が出る）、「元にした文章」に「自分の発言」の行が 1 本ずつ増える。保存された文章にも Codex への指示にも、名前・時刻・画面の文字と、他人の発言にしか無い語が 1 つも無い。同じ会話をもう一度貼っても行は増えない。道具の名前を選ぶ場面は一度も無い。
7. 会話でないふつうの文章（「」の会話文を含む）を貼ると、名前の一覧も確認も出ず今までどおり空行で分かれる。取り込みに失敗しても（選んだ人の発言が 1 つも残らない会話を含む）平易な一文が出て、何も保存されず、「題を出す」は押せる。

## lita-ux への引き継ぎ

### 頼むこと

① 必須 1〜6 の「その場で文章を足す」を、案 C の画面（`c-4.png` の空いた場所）に入れる設計をしてください。静的 HTML で 1〜2 案、撮る場面は 4 つ: ①文章 0 本で開いた ②次の一手を押して取り込み部品が開いた ③貼って足した直後に言葉を拾っている ④雲が出た。

② 必須 16〜25 の「どのチャット・メールからの会話を貼っても本人の発言だけが残る」を、①と**同じ貼る欄**（`PasteBox`）の中で設計してください（2026-09-26 に 2 回改訂。~~Slack の検索結果を貼ると本人の発言だけが残る~~ → 道具を問わない形、D-77。書き出しを落とす行は段 5 なので設計しない）。①と同じ静的 HTML の中で。撮る場面は 5 つ: ⑤欄が開いていて、会話を貼っても自分の発言だけが残ることの 1 文が見える ⑥初めて会話を貼った直後（話者の名前の一覧と「全部が自分の文章」）⑦2 回目以降（覚えた名前で足す 1 文と「変える」、残る本文の見え方）⑧時刻はあるのに話者を分けられなかったときの一文 ⑨足した後の「自分の発言」の行（「元にした文章」の並びの中で）。

### 守る制約

- **主ボタンは「題を出す」のまま**（原則 3）。次の一手は薄いリンクか一文＋リンク。取り込み部品の中の「足す」ボタンが主ボタンと並んで見えないようにする。
- **次の一手は 1 つ**（原則 6）。「貼る」「つなぐ」を並べるのは開いた先で（会話も「貼る」の中）。
- **約束だけの一文を出さない。** 一文を置くなら、同じ行に押せる次の一手がある形に（例「自分の文章を足すと、よく書いている言葉がここに出ます。 文章を足す」は可。数字は入れない）。
- 取り込み部品は**既存のものをそのまま使う**（`SourceBox.tsx`・`PasteBox.tsx`、D-60・D-65）。この画面のために別の貼る欄を作らない。**道具ごと（Slack・LINE など）の欄・ボタン・タブ・モーダル・アイコンを作らない**（貼る欄が貼られたものの形を見分ける）。
- 会話を貼れることの説明は **1 文まで**（X の「設定から申請したアーカイブを選びます。」と同じ重さ）。道具の名前・検索の記法・手順の図・番号つきの手順は出さない。貼る欄のふだんの説明（「気に入っている文章を、まとめて貼れます。」）と競わない置き方に。
- 本人を選ぶ名前の一覧に**数字（発言数）を出さない**（原則 2）。会話のときは「n 本として読みます」「1 本にまとめる」を出さない（1 回の貼り付けは 1 本）。名前の一覧は初回（覚えた名前が候補に無いとき）だけ出し、欄の中でその場に開く（モーダルにしない）。一覧の最後の「全部が自分の文章」は名前と同じ重さの選択肢に。
- 「自分の発言だけを残します」の趣旨の一文は欄の中に 1 つだけ。警告の色にしない（正常時は静か）。覚えた名前で足すときに確認のボタンを挟まない（違うときだけ「変える」で選び直せる）。
- 語は「文章」「元にした文章」「言葉」「発言」。「学習」「材料」「ソース」「データ」を出さない（原則 1）。足した文章が文体の「元にした文章」に入ることは、言うなら開いた部品の中で一文だけ。
- 案 C の画面の組み立て（入力欄 0・主ボタン 1・編集方針はリンク）を崩さない。
- 色・角丸・書体はトークンから（原則 8）。
