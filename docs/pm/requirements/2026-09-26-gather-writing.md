## 目的

案 C（D-71）で、言葉の雲は題を向ける**唯一の手段**になりました。雲が出ない人は、押すものが 1 つも無い画面に立たされます。**その人の文章そのものを集めて、最初の起動から雲が出るまでの距離を縮めます。** 入力欄で埋め合わせることはしません（D-72）。

### 日常の文章の集め先（2026-09-26 追記）

本人の回答で、公開記事の外にまとまった文章は少なく、**日々書いている量はチャットやメールのほうが多い**ことが分かりました。雲にとって大事なのは「何について書いているか」なので、口語のチャットでも題材の語はよく出ます。一方で、チャットには**他人の発言**と**社内の話**が混ざります。経路はこの 2 点で選びます。

#### 守る条件（AGENTS.md・既存の決定から）

| 条件 | 中身 |
| --- | --- |
| Lita の運用サーバを持たない・テレメトリなし | 取り込みは手元で読んで、本人の文章だけを既存の保存先（`voice_sources`、Supabase、D-36・D-40）に入れる。書き出しファイルそのものはどこにも置かない |
| 審査や権限の壁を越えない | Slack の API は凍結（D-42）。Gmail の読み取りは制限付きスコープで審査が要る。API を使わない経路にする |
| 他人の発言を混ぜない | 保存するのも Codex に送るのも本人の発言だけ。他人の発言は読んだその場で捨てる。本人の発言の中の他人のメンションも消す |
| 本人が選ぶ | 何を入れたかが「元にした文章」で見え、1 行で外せる（D-57）。入れる前に、入れたくない会話を外せる |

| 経路 | 中身と実態 | 本人の発言だけを抜けるか | 判定 |

#### 推奨

**「書き出しファイルを落とすと、本人の発言だけを抜いて足す」を 1 つの入口にし、最初の対象を Slack の書き出し ZIP にします。** 理由は 4 つです。

1. **本人が最初に挙げたのが Slack**で、仕事の文章が最も多い場所です（D-05 で最初の文体の材料に選んだ理由と同じ）。
2. **API も審査も使わないので、D-42 の壁に当たりません。** 書き出しは Slack の標準機能で、Lita は手元のファイルを読むだけです。
3. **本人の発言だけを確実に抜けます。** メッセージごとに送り手の ID があり、名前で推測する必要がありません。
4. 入口を「書き出しファイル」1 つにしておけば、あとで Gmail・Discord・LINE の読み手を足しても画面の入口は増えません（原則 1・6）。

弱点は、**Slack の所有者・管理者でないと書き出しを取れない**ことです。本人が取れない場合は、最初の対象を Gmail の送信済みメールに替えます（残る質問 1）。

## 必須

### 1. その場で文章を足す

1. **雲が出ないとき**（材料が無い、言葉が下限に満たない）、「書く題を決める」の雲の場所に**次の一手が 1 つだけ**出ます。薄いリンクまたは一文＋リンクで、主ボタンは「題を出す」のままです（原則 3・6）。約束だけの一文は出しません。
2. 押すと、**画面を離れずに**既存の取り込み部品（自分の文章を貼る欄・.txt/.md を落とす場所・note／Medium／X をつなぐ行、D-60・D-65）がその場に開きます。モーダルにしません。閉じれば元に戻ります。
3. 足した文章は、**直近の記事の文体**（D-55 と同じ選び方。文体が 1 つならそれ）の「元にした文章」に入ります。文体ページの「元にした文章」に、1 本 1 行で同じものが並びます（**本人の回答で確定、2026-09-26**。次に学び直すと文体にも効きます）。
4. 文章を足しても**文体は学び直しません**。学び直すかは今までどおり文体ページで本人が選びます（D-57）。
5. 足し終えたら、**画面を離れずに自動で言葉を拾い**、雲が出ます。拾っている間の見せ方と中止は、今の「拾う」と同じです（D-66 必須 9）。
6. 文章 0 本の文体（おすすめの文体、D-70）でも同じ次の一手が出ます。文体が 1 つも無いときは、今までどおり「まず文体を作りましょう」が先です。

### 2. 取りこぼさない

7. **言葉が下限に満たない雲が保存されていても**、そのあと本人の文章が増えていれば、画面を開いたときに**自動で 1 回拾い直します**。言葉が十分な雲は、今までどおり自動では拾い直しません（D-66 必須 7 を維持）。
8. **雲を出す下限を 5 語から 3 語に下げます**（雲の要件の必須 16 を改訂）。Codex への指示は「材料が支える数だけ。最大 40（狙い 30）」に変え、材料が少ないときに一般語で水増しさせません。
9. **雲を拾うときに読む量を広げます。** 24 本・各 400 字の上限を雲では外し、**全部の文章を、全体 40,000 字の中で読みます。** 1 本あたりは全体を本数で割った長さ（最大 2,000 字。頭と末尾から取る）で、本数が多いほど 1 本は短くなりますが、落とす本はありません。題を出すとき（`topics_prompt`）の読み方は変えません。
10. **材料の数（「新しい文章が増えています」の判定）は、本人の文章だけで数えます**: 元にした文章の本数＋本人が直した記事の本数（必須 11 の定義）。Lita が積んで書いただけの記事では増えません。

### 3. 使うほど育つ

11. **本人が直した記事の本文を材料に入れます。** 「直した」とは、Lita が最後に書いた版（`generated`・`shortened`）から本文が変わっている記事、または Lita が一度も書いていない記事です。Lita が書いたままの記事の本文は入れません。題と 1 行目は今までどおり「もう書いた題材」の判定に使います。
12. 本人が直した記事を材料に入れても、**生成の契約（D-28・D-29・D-59）と文体は変えません**。雲のプロンプトにだけ入ります。

### 共通

13. **数字を出しません**（本数・字数・語数・「あと n 本」）。取り込み部品が既に出している表示（「n 本として読みます」など）はそのままです（原則 2）。
14. 取り込みや拾うのに失敗したときは、既存の平易な一文を出し、**画面の残りと「題を出す」は使えるまま**です（原則 7）。前の雲があれば残します。
15. 画面の語は「文章」「元にした文章」「言葉」。「学習」「ソース」「材料」「データ」は出しません（原則 1）。

### 4. 日常の文章から集める（2026-09-26 追記、段 4）

16. 「書いた場所からつなぐ」の器（`SourceBox`）に、**チャットの書き出しを落とす行が 1 つ**増えます。文体の入口・文体ページの「元にした文章」・「書く題を決める」のその場で足す欄（必須 2）のどこでも同じ行です。この画面専用の入口は作りません。
17. その行に **Slack の書き出し ZIP** を落とす（または選ぶ）と、Lita は手元で読み、**本人が送ったメッセージだけ**を取り出します。bot・連携アプリの投稿、参加・退出などの `subtype` 付きの記録、他人の発言は、読んだその場で捨てます。
18. 本人の見分け方: Lita のサインインのメールアドレスと `users.json` のメールが一致すればその人。一致しなければ、**本人が名前の一覧から自分を 1 回選びます**（一覧は書き出しに発言がある人だけ、名前だけ）。選んだ結果は同じワークスペースの次の取り込みに使い、他人の名前は保存しません。
19. 本人の発言からも、**他人を指すものを消します**: メンション（`<@U…>`）、引用行（`>` で始まる行）。リンクは表示の文字だけ残し URL は消します。絵文字の記法（`:smile:`）とコードの塊も消します。
20. **入れる前に、入れたくない会話を外せます。** 本人の発言がある会話の名前が並び、既定は公開チャンネルがすべて入り、DM・非公開の会話（書き出しに含まれる場合だけ）は外れています。数字は出しません（原則 2）。
21. 保存の単位は **1 つの会話の 1 日ぶんの本人の発言を 1 本**とし、`voice_sources` に新しい種類（例 `chat`）で入ります。連携先の鍵はワークスペース（例 `slack:<チーム ID>`）で、「元にした文章」では**1 つのつないだ行**（名前は「Slack」。ワークスペースが 2 つ以上なら ZIP の名前から見分けを足す）として並び、「外す」で全部外せます（D-57 と同じ）。同じ本を二度入れないよう、会話と日で重複を除きます。新しい書き出しを落とせば、増えた日の分だけ足されます。
22. **書き出しファイルそのものは保存しません。** 読み終えたら手元にもサーバにも残しません。サーバ（D-36）に入るのは必須 21 の本人の文章だけで、Codex に渡るのもそれだけです。
23. 取り込んだ直後は、必須 5 と同じく**画面を離れずに自動で言葉を拾います**（「書く題を決める」から開いたとき）。文体は学び直しません（必須 4、D-57）。
24. ZIP が Slack の書き出しでない、本人の発言が 1 つも無い、壊れている、のいずれでも、平易な一文で伝えて何も保存しません（原則 7）。
25. プライバシーの一文を行の中に 1 つだけ置きます（趣旨「自分の発言だけを残します。ほかの人の発言は保存しません。」）。公開サイトのプライバシーポリシー（`site/privacy.html`）に、チャットの書き出しから本人の発言だけを保存することを書き足します（handoff「扱うデータが変わったらここも直す」）。

## 任意

- 任意の URL から 1 本ずつ取り込む（洗い出しの 4）。本人の回答（2026-09-26）で**任意のまま**。
- つないだ note・Medium の新しい記事を、この画面を開いたときに静かに取り込む（5）。
- .docx・.pdf の取り込み、.txt・.md をフォルダごと落とす（6）。
- おすすめの文体を選んだ直後に、文章を足すと題の言葉も出ることを一文で伝える（7）。
- 雲の言葉に指を載せたとき、その言葉が出てくる本人の文章の一節を 1 つ見せる（雲の要件の任意と同じ）。

## やらないこと

- **話題・題材を書かせる欄**、雲に言葉を手で足す機能、オンボーディングの質問（D-72）。
- Slack・Gmail・Teams・Google ドライブを **API でつなぐこと**（D-42。審査と権限の壁）。書き出しファイルの取り込み（必須 16〜25）はこれに当たらない。
- **クリップボードの常時監視**、キー入力や画面の読み取りなど、本人が選ばずに文章を集めること。
- macOS の共有メニュー（Share Extension）。別ターゲットと署名が要り、D-51（署名は保留）と衝突する。
- **他人の発言を保存すること、Codex に渡すこと。** 書き出しファイルそのものを保存すること。
- 書き出しの定期取り込み（Slack の定期書き出しを見張るなど）。新しい書き出しは本人が落とす。
- Lita が書いたままの本文、Lita が出した題、積んだだけの記事を材料にすること。
- 題材のための別の置き場所（新しいテーブル・新しい名前）。足した文章は「元にした文章」に入る（本人の回答で確定）。チャットの発言は `voice_sources` の新しい種類で、置き場所は同じ。
- 文体の自動の学び直し（D-57）。
- 題を出すとき（`topics_prompt`）の材料の読み方を変えること（待ち時間に効くため）。
- 案 C の画面の組み立て（`2026-09-26-topics-press-only.md`）を変えること。

## 受け入れ条件

1. おすすめの文体だけ（文章 0 本・記事 0 本）で「書く題を決める」を開くと、雲の場所に次の一手が 1 つだけあり、約束だけの一文は無い。
2. その一手を押すと画面を離れずに貼る欄とつなぐ行が開き、1,500 字ほどの自分の文章を 1 本貼って足すと、画面を離れずに言葉が拾われて雲が出る。足した文章は文体ページの「元にした文章」に 1 本 1 行で並び、文体の 8 項目は変わっていない。
3. 言葉が下限に満たない雲が保存された状態で文章を足し、この画面を開き直すと、「拾い直す」を探さなくても自動で拾い直して雲が出る。
4. 文章を 30 本つないだ状態で拾い直すと、25 本目以降の文章にしか出てこない題材も雲に入る。
5. 記事を 3 本積んで書き上がっただけでは「新しい文章が増えています」は出ず、そのうち 1 本の本文を本人が直してから開くと出る。
6. 本人と他人の発言が混ざった Slack の書き出し ZIP を落とすと、「元にした文章」に「Slack」の行が 1 つ増え、保存された文章にも Codex への指示にも、他人の発言にしか無い語が 1 つも無い。
7. 取り込みに失敗しても（Slack の書き出しでない ZIP を含む）平易な一文が出て、何も保存されず、「題を出す」は押せる。

| 次の一手の数 | 1 つ（貼る・落とす・つなぐは開いた先に並ぶ） | 原則 6。入口を 3 つ並べると、どれを選ぶかの判断が要る |

## lita-ux への引き継ぎ

### 頼むこと

① 必須 1〜6 の「その場で文章を足す」を、案 C の画面（`c-4.png` の空いた場所）に入れる設計をしてください。静的 HTML で 1〜2 案、撮る場面は 4 つ: ①文章 0 本で開いた ②次の一手を押して取り込み部品が開いた ③貼って足した直後に言葉を拾っている ④雲が出た。

② 必須 16〜25 の「チャットの書き出しを落とす行」を、同じ器（`SourceBox`）に足す設計をしてください。①と同じ静的 HTML の中で。撮る場面は 5 つ: ⑤行が閉じている ⑥ZIP を落として読んでいる ⑦本人を選ぶ一覧（メールで見分けられなかったとき）⑧入れたくない会話を外す一覧 ⑨入った後の「Slack」のつないだ行。

### 守る制約

- **主ボタンは「題を出す」のまま**（原則 3）。次の一手は薄いリンクか一文＋リンク。取り込み部品の中の「足す」ボタンが主ボタンと並んで見えないようにする。
- **次の一手は 1 つ**（原則 6）。「貼る」「つなぐ」「書き出しを落とす」を並べるのは開いた先で。
- **約束だけの一文を出さない。** 一文を置くなら、同じ行に押せる次の一手がある形に（例「自分の文章を足すと、よく書いている言葉がここに出ます。 文章を足す」は可。数字は入れない）。
- 取り込み部品は**既存のものをそのまま使う**（`SourceBox.tsx`・`PasteBox.tsx`、D-60・D-65）。この画面のために別の貼る欄を作らない。チャットの行も既存の行（note・Medium・X）と同じ畳み方・同じ「✓ つないだ行」にする。
- チャットの行の名前は書き出しの種類ごとに増やさない（のちに Gmail・Discord が乗る）。ヒントで「Slack の書き出し」と分かれば足りる。書き出しの取り方の説明は 1 文まで（X の「設定から申請したアーカイブを選びます。」と同じ重さ）。
- 本人を選ぶ一覧・外す会話の一覧に**数字（発言数・本数）を出さない**（原則 2）。一覧は長くなりうるので、既定のままで「足す」を押せば済む形に。
- プライバシーの一文は行の中に 1 つだけ（必須 25）。警告の色にしない（正常時は静か）。
- 語は「文章」「元にした文章」「言葉」「発言」。「学習」「材料」「ソース」「データ」を出さない（原則 1）。足した文章が文体の「元にした文章」に入ることは、言うなら開いた部品の中で一文だけ。
- 案 C の画面の組み立て（入力欄 0・主ボタン 1・編集方針はリンク）を崩さない。
- 色・角丸・書体はトークンから（原則 8）。
