# 学習ソースの行を「どれか一つで足りる」と読めるようにする

- 出所: 本人の一言（2026-09-23）「ここのUIもっと任意感を強くしたいです」。対象は取り込み画面「あなたの書き方を Lita に教える」の連携先ボックスと、文体ページ「学習ソース」の同じボックス（`SourceBox.tsx`）
- 関係する決定: D-43（入口は公開済みの発信の取り込み、貼り付けは受け皿）、D-56（取り込みは一本道、数字を出さない）、D-57（連携先はサービスをまたいで何件でも足せる、連携先ごとに外せる）。UX レビュー 2026-09-23 の ⑤ と原則（正常時は静か、数字は困るときだけ、主ボタンは画面に 1 つ、一つの概念に一つの名前）

## 目的（1〜2 文）

連携先の 4 行（note／Medium／X／手作業）が「全部埋める欄」ではなく「どれか一つをつなげば進める選択肢」だと、説明を読まなくても分かるようにします。つないだ場所が主役で、残りは「あとで足してもよい」入口に見えることが狙いです。

## 利用者の状況

- **初回（文体がまだ無い）**: 取り込み画面を開くと、入力欄つきの行が 4 つ縦に並び、主ボタンはありません。どこまでやれば次へ進めるのかが画面から読めず、4 欄のフォームに見えます（`intake.png`）
- **1 つつないだ直後**: note が「✓ note・kuno 10 件 外す」に変わり、下に「10 件の文章を使います」と「文体を作る」が出ます。しかし Medium と X の行は入力欄・ボタン・注記がそのままの大きさで残り、「まだ埋めるところがある」ように読めます（`intake-loaded.png`）
- **文体ページで足す・外す**: つないだ行 3 つの間に、つないでいない X と手作業の行が同じ重さで挟まっています。「学んだ場所」の一覧なのか、「足す場所」の一覧なのかが混ざっています（`voice-sources.png`）
- 想定利用者は本人 1 人。多くは note か X の一方だけをつなぎます

## 必須（番号つき、検証できる文）

1. 取り込み画面の空の状態で、ボックスの上か中に「どれか一つで足りる」という趣旨の一文が出ます。現在の「つなぐ場所はいくつでも。」はこの一文に置き換えます（「いくつでも」だけでは最低数が伝わりません）
2. 空の状態でも、4 行は「未記入の欄」ではなく「選べる入口」として並びます。入力欄と「つなぐ」は、その行を選んだときに開けば足ります（開き方は lita-ux が決める）。ただし各行の一行目の名前（note／Medium／X／手作業）と短い説明は最初から読めること
3. 1 つ以上つながったら、つないだ行がボックスの中で最も重く、つないでいない行はそれより軽く見えます。軽い行は入力欄を開いたまま置かず、一手で開けます（取り込み画面・文体ページとも）
4. 取り込み画面では、1 つの場所から 1 件以上入った時点で、名前の行（「「note・kuno」という名前で保存します」）と「文体を作る」が出て押せます。これが「もう進める」合図であり、ほかに合図は足しません。「文体を作る」は画面で唯一の主ボタンです
5. 「足りない」ことは困るときだけ言います。つないだ結果が 0 件（`import.nothingNew`）で使える文章が 0 のときに限り `ready.none` を出し、それ以外の場面で「必須」「あと n 件」「任意」といった印や数字を各行に付けません
6. 手作業の行は両方の画面で残し、常に最後、最も軽い入口として置きます。「自分で書く・貼る」「テキストファイルを選ぶ」の動作は変えません
7. つないだ行は現在の形（✓・連携先の名前・件数・「新しい記事を取り込む」（文体ページのみ）・「外す」）を保ちます。「外す」で最後の 1 つを外したら、ボックスは空の状態（必須 1・2）に戻り、取り込み画面では名前の行と「文体を作る」が消えます。エラーは出しません
8. ある行で取得中・失敗中でも、ほかの行は使えます。失敗はその行の中に平易な一文＋「詳細を表示」で出します（現在の `ErrorNote` のまま）
9. 軽くした行もキーボードで到達でき、開いたときにその行の入力欄へフォーカスが移ります。スクリーンリーダーには行の名前が読み上げられます
10. 文言は既存の語を使います。動作は「つなぐ」、場所は「場所」、文体ページの見出しは「学習ソース」。「連携」「追加する」「登録」などの新しい語を持ち込みません

## 任意

- 軽い行をまとめて 1 行（例: 「ほかの場所もつなぐ: Medium・X・手作業」）に畳み、押すと行が開く形。必須 3 を満たす一案として lita-ux が採否を決めてよい
- 空の状態で、本人がいちばん使う note の行だけを少し前に出す（D-43 の順序 note → Medium → X）。ただし「note が必須」に見えない範囲で
- 文体ページで、つないだ行と軽い行の間に細い区切りを置く

## やらないこと

- 同じサービスの複数アカウント（note 2 つなど）をこのボックスから足せるようにすること。今の `SourceBox` の制約（サービスごとに 1 行）のままにします
- 行の順序の変更、X の「返信も含める」や有料記事の注記など、各行の中身の仕様変更
- 取り込み後の「n 件の文章を使います・見直す」やタイル群の変更（D-56 の範囲で確定済み）
- 「この材料で学び直す」の位置・文言・確認の変更
- 新しいオンボーディング（手順の番号、ガイドツアー、空状態のイラスト）を足すこと。番号は D-56 で外しました

## 受け入れ条件（画面を見て Yes/No で判定できる文、最大 7）

1. `?scene=intake` で、「どれか一つで足りる」趣旨の一文が見え、「つなぐ場所はいくつでも。」は無い
2. `?scene=intake` で、4 行のどれにも「必須」「任意」の印や数字が付いておらず、ボックスの中に主ボタンが無い
3. `?scene=intake-loaded` で、「✓ note・kuno 10 件」の行がボックスの中で最も重く、Medium・X・手作業の行はそれより軽く、開いた入力欄がフルサイズで残っていない
4. `?scene=intake-loaded` で、「文体を作る」が画面で唯一の主ボタンとして押せる状態で見え、名前の行がその隣にある
5. `?scene=voice-sources` で、つないだ 3 行（note・Medium・貼った文章）と、つないでいない X・手作業の行の重さが一目で区別できる
6. 軽い行を 1 回押すと、その行の入力欄（または「tweets.js を選ぶ」）がその場に開き、入力欄にフォーカスが当たる
7. `intake-loaded` で「外す」を押すと、ボックスが `intake` と同じ空の状態に戻り、名前の行と「文体を作る」が消え、エラーが出ない

## 本人に聞かずに決めた既定値（表: 項目｜決めた値｜理由）

| 項目 | 決めた値 | 理由 |
| --- | --- | --- |
| 「足りる」の基準 | 1 つの場所から使える文章が 1 件以上 | `ready.none` と `use.count` の現行判定と同じ。文体は 4 件でほぼ安定するが（実測）、最低数は「困るときだけ」の原則で画面には出さない |
| 「一つで足りる」の伝え方 | リード文の一文で 1 回だけ言う。各行に「（任意）」を付けない | 4 行に同じ印が並ぶと騒がしく、「静かにする」原則に反する。任意なのは全行なので、行ごとに言う意味がない |
| リード文の文言（案） | 「気に入っている文章のある場所を、どれか一つつなぐだけで足ります。あとから足したり外したりできます。」 | 「いくつでも」より先に最低数を言う。「あとから足せる」で D-57 の可逆性も伝わる。文言の最終形は lita-ux |
| 軽い行の形 | 一行目（名前と短い説明）だけを見せ、入力欄は選んだときに開く | 空の入力欄が並ぶと「埋めるもの」に見えるのが今回の原因。開くのは一手で、閉じたままでも何の行かは分かる |
| 軽い行の適用範囲 | 空の状態から軽くする（1 つつないだ後だけではない） | 初回はつないだ行が無いので、比較対象がないまま 4 欄のフォームに見える。空でも「選択肢」として並ぶ必要がある |
| 手作業の位置と重さ | 最後、最も軽い入口として残す | D-43 で貼り付けは受け皿。消すと文章の置き場が無い人が詰まる |
| 進める合図 | 既存の名前の行＋「文体を作る」だけ | 主ボタンは画面に 1 つ。合図を増やさない |
| 最後の 1 つを外したとき | 空の状態に戻す（確認なし。文体ページは既存の確認のまま） | 取り込み画面ではまだ何も保存していないので確認は要らない。文体ページは D-57 の「学び直すまで変わらない」確認を維持 |
| 文体ページでの見せ方 | 隠さず、軽くして同じボックスに置く | 「追加する」で開く形（`voice.sources.add` は未使用のキー）にすると、足せることが見えなくなる。ただし残る質問 1 を参照 |

## 残る質問（最大 3、無ければ「なし」）

1. 文体ページの「学習ソース」で、つないでいない行を**同じボックスに軽く置く**（既定値）か、**「ほかの場所をつなぐ」の 1 行に畳んで押したときだけ開く**か。後者は一覧が「学んだ場所」だけになって読みやすい反面、足せることが一手遠くなります。取り込み画面は既定値どおり同じボックスで進めます

## lita-ux への引き継ぎ（設計で守るべき制約、参考にすべき既存画面）

- **守る原則**: 正常時は静か（印・数字・ゲージを足さない）。主ボタンは画面に 1 つ（「文体を作る」／「この文体で書く」）。一つの概念に一つの名前（つなぐ・場所・学習ソース）。ミント 1 色・角丸 8px/12px・`App.css` のトークンだけで組む
- **重さの表現の候補**: 文字色 `--mute`、行の高さ、入力欄を閉じる、の 3 つで差を付ける。新しい色や枠線の種類は足さない
- **両画面で同じ部品**: `SourceBox` は取り込み画面（`hero`）と文体ページで共通。設計は 1 つで、`hero` の有無だけで余白が変わる前提にする
- **既存画面の参考**: 文体ページの「▸ 詳細を見る（口調、言葉、組み立て）」の `details` 行が「畳んだ入口」の既存の型。取り込み後の「10 件の文章を使います。見直す」も同じ「一行に畳む」型。軽い行はこれらと同じ調子に揃える
- **文言の器**: `voice.intake.more`（差し替え）、`import.noteHint` / `mediumHint` / `xHint`（軽い行では一行目の短い説明になる可能性がある）。新しいキーは最小限に
- **確認する場面**: モックの `intake` / `intake-loaded` / `voice-sources` の 3 場面で受け入れ条件 1〜7 を判定する。行を開いた状態のシーンが要るなら `src/platform/mock.ts` にシーンを 1 つ足してよい
