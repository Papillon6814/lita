# 検証記録: 生成の待ち時間（B-10 / Issue #3）

- **実施日**: 2026-09-22
- **環境**: Codex CLI 0.154.0 / auth_mode = chatgpt
- **再現方法**: `cargo run -p lita-codex --bin probe`

## 結論

**「約30秒の無音」という問題設定が間違っていました。**

PoC で測った26.6秒は、Voice プロファイルを丸ごとプロンプトに入れた状態の値でした。条件を変えて測り直したところ、**短いプロンプト＋推論量 low で 6.6秒**まで落ちます。品質の劣化は見えませんでした。

7秒なら、チャット AI でおなじみの「生成中」インジケータで足ります。無音を埋める工夫は要りません。

## 実測値

X 用ポスト1本の生成（短いプロンプト）:

| 条件 | 所要 | 出力トークン | 推論トークン |
| --- | --- | --- | --- |
| そのまま（推論 medium） | 10.8秒 | 147 | 83 |
| `--ignore-user-config` | 10.4秒 | 73 | 0 |
| 推論量 low | **6.6秒** | 61 | 0 |

同じポスト生成でも、**Voice プロファイル全文をプロンプトに入れると 26秒**かかりました。Voice 抽出（8メッセージ）は実行ごとに **45〜65秒**と振れます。

**レバーは2つあります。推論量とプロンプトの大きさです。** どちらも Lita 側で制御できます。

## 分かったこと

### ストリーミングはやはり出せない

Codex は進捗を stderr に流すと書かれているため確かめましたが、**中身は空振り**でした。流れてきたのは無関係な MCP サーバーの OAuth エラー1行だけです。

つまりチャット AI のように**文字が流れる表示は作れません**。出せるのはインジケータそのものです。7秒ならそれで十分だと判断しました。

### ユーザーの Codex 設定を引き継いでいた

検証中、Lita の生成が**本人の Notion MCP 設定を読み込んでエラーを出していました**。

```
ERROR codex_rmcp_client::oauth::refresh_transaction:
  failed to refresh OAuth tokens for server notion
```

Lita の生成結果や速度が、その人の Codex プロファイル・AGENTS.md・MCP サーバー構成に左右されるのは避けるべきです。`--ignore-user-config` を常時付けることにしました。**認証は `auth.json` にあり `config.toml` とは別なので、ログインは維持されます**（実測で確認済み）。

なお、入力トークンは約17,000で、`--ignore-user-config` を付けても減りませんでした。これは Codex 自身のシステムプロンプトとツール定義の分です。削れません。

## 決めたこと

- 推論量は**ユーザーが選べる**ようにする（速度重視 = low / 品質重視 = medium）。短文では差が見えなかったが、長文で差が出る可能性を否定できないため、こちらで固定しない
- ポスト生成は**インジケータのみ**
- Voice 生成（45〜65秒）は**ステージ表示**を出す。ただし Codex はイベントを4種類しか返さないので、**段階表示は演出であり実態ではない**。承知のうえで採用する
- `--ignore-user-config` を常時付ける

## 設計メモ

プロンプトの大きさが待ち時間に直結します。生成時に Voice プロファイルを整形済み JSON で丸ごと渡すと26秒かかりました。**生成に効く項目だけを渡す形に絞る余地があります**（`representative_excerpts` を全文入れる必要があるかなど）。Voice スキーマを確定するとき（B-04）に併せて考えます。
