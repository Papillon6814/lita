## 2026-09-22 — 待ち時間の実測を受けて

検証記録: [`docs/pm/2026-09-22-latency.md`](2026-09-22-latency.md)

| # | 論点 | 決定 | 理由・補足 |
| --- | --- | --- | --- |
| D-23 | 生成中の見せ方 | **チャット AI と同じ「生成中」インジケータ。文字は流さない** | Codex の stderr に進捗の中身はなく（確認済み、流れてきたのは無関係な MCP エラーのみ）、`--output-schema` を使う以上、答えは最後に一括で届く。**ただし短文生成は6.6秒まで落ちるので、埋めるべき無音がそもそもない** |
| D-24 | 推論量（reasoning effort） | **ユーザーが選べるようにする。速度重視 = low / 品質重視 = medium** | 短文では品質差が見えなかったが、長文で差が出る可能性を否定できない。こちらで固定せず本人に委ねる。`Effort` enum として実装済み |
| D-25 | ユーザーの Codex 設定の扱い | **`--ignore-user-config` を常時付ける** | 検証中、Lita の生成が本人の Notion MCP 設定を読み込んで OAuth エラーを出していた。生成結果や速度が他人の Codex 構成に左右されるのは避ける。**認証は `auth.json` にあり `config.toml` とは別なので、ログインは維持される**（実測確認済み） |
| D-26 | Voice 生成（45〜65秒）の見せ方 | **ここだけステージ表示を出す** | 初回セットアップの1回きりとはいえ、1分近い無音は重い。**ただし Codex はイベントを4種類しか返さないので、段階表示は演出であり実態ではない。承知のうえで採用する** |
