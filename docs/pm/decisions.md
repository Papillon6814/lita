## 2026-09-22 — Slack の権限要件の検証を受けて

検証記録: [`docs/pm/2026-09-22-slack-scopes.md`](2026-09-22-slack-scopes.md)

| # | 論点 | 決定 | 理由・補足 |
| --- | --- | --- | --- |
| D-20 | v0.1 の Voice ソースをどうするか | **Slack API 依存をやめ、本人が選んで貼った文章にする。Slack ボタン連携は v0.2 以降に延期**（D-05 / D-12 / D-13 を改訂） | 理由は2つ。(1) **Slack 側がほぼ塞がっている** — `search.messages` は公式が名指しで非推奨、後継の RTS API は unlisted distributed app に非開放、`conversations.history` はレート制限以前に形が合わない（全員の発言が返る）。マニフェスト配布の抜け道も更新後の API 利用規約が名指しで塞いでいる。(2) **そもそも大量取得が要らなかった** — 実測で Voice は4件でほぼ安定し、24件との差は語彙の豊かさだけだった。数十件で足りるなら、本人が選んだ20件のほうが機械的に集めた500件より良い Voice になりうる |
| D-21 | v0.1 の完成定義（改訂版） | **気に入っている文章を20件ほど貼る → Voice を1つ生成 → ブリーフ入力 → X 用ポスト生成 → 承認 → クリップボードにコピー、が一周する** | D-13 の骨格（1ボイス × 1プラットフォーム）は変えず、入口だけを Slack 連携から貼り付けに差し替えた |
| D-22 | Slack 関連の未検証項目をいつ潰すか | **方針が固まってから。v0.1 では調べない** | 公開配布と `lita://oauth` の両立、`search:read` が今も取得可能か。いずれも Slack App の作成が必要で、PKCE の有効化は取り消せない。v0.2 で Slack に戻るときにまとめて確かめる |
